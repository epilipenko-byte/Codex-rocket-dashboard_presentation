# CODEX_EDITION_2_2026-07-07 — протокол решений и разногласий

Этот документ фиксирует решения Edition 2. Он применяется поверх ТЗ v3.1, ТЗ v4 и протокола Edition 1, включенных в этот пакет без изменений.

## Главный принцип

Edition 2 не является косметическим исправлением Edition 1. Это новая управленческая версия дашборда: данные должны собираться по названиям строк и стабильным ключам периода, а интерфейс должен показывать, какие строки источников вошли в расчет.

## Решения Edition 2

| ID | Раздел | Решение | Статус |
|---|---|---|---|
| E2-001 | Публикация | Edition 2 публикуется отдельно, с `edition-2` и датой в имени GitHub-ресурса. Edition 1 не перезаписывать. | Принято |
| E2-002 | Периоды | Источник истины периода — `month_keys`, например `2026-01`; текстовые месяцы используются только как подписи. | Принято |
| E2-003 | Периоды | Фронт строит селекторы, заголовок периода, KPI, графики и таблицы только из `month_keys/months`, полученных от proxy. | Принято |
| E2-004 | Периоды | Пустые будущие месяцы без полезных числовых данных не становятся диапазоном по умолчанию. | Принято |
| E2-005 | Маржинальности | Процентные маржи брать из готовых строк источника по названию. Расчет на фронте — только fallback. | Принято |
| E2-006 | D/E | D/E считается по процентному долгу: займы/кредиты/interest-bearing debt. Операционная кредиторская задолженность не входит. | Принято |
| E2-007 | P&L | Водопад P&L строится из нормализованных строк отчета; расходы показываются красным вниз, прибыль/доходы зеленым вверх. | Принято |
| E2-008 | P&L расходы | Группировка расходов: трафик, вся зарплата, все IT сервисы, прочие переменные, общехозяйственные, косвенные + ниже EBITDA. | Принято |
| E2-009 | P&L таблица | Таблица ОПиУ раскрываемая: агрегированные строки раскрывают входящие строки; нулевые будущие месяцы скрываются. | Принято |
| E2-010 | Проекты | Вкладку `ОПиУ блоки` переименовать в `Проекты Rocket`; каждый проект отображать как раскрываемый управленческий блок. | Принято |
| E2-011 | Консолидация | Вкладку `Консолидация` переименовать в `Ludens Group` или `Ludens Gr.`. | Принято |
| E2-012 | ДДС | Главный общий денежный поток — `Total NCF — Monthly Cash Change`, если строка найдена. Если нет, fallback — сумма NCF Operational/Investment/Financial. | Принято |
| E2-013 | ДДС | Строки после трех блоков ДДС не игнорировать: займы, дивиденды, конвертации, переоценки, internal transfers показывать в отдельном блоке. | Принято |
| E2-014 | Cash | Остаток ДС и balance/snapshot KPI берутся на конец выбранного периода `period_to`, а не на текущий месяц. | Принято |
| E2-015 | Результаты | `Задачи` и `Результаты` объединить во вкладку `Результаты`; старые пороговые карточки назвать `Целевые метрики`. | Принято |
| E2-016 | Ссылки | Вкладка `Результаты` должна показывать карточки ссылок из Dashboard Config типа `dashboard_link`. | Принято |
| E2-017 | Техлист | Последняя вкладка `Тех. лист` показывает Dashboard Config и диагностику в таблицах, похожих на исходный Config. | Принято |
| E2-018 | ЦКП | ЦКП много; строить блоки автоматически по всем найденным ЦКП, а не ограничиваться двумя-тремя. | Принято |
| E2-019 | Заметки докладчика | Заметки редактируются прямо из дашборда и сохраняются через Apps Script. | Принято |
| E2-020 | Заметки докладчика | Основная привязка заметок — к визуальному блоку графиков (`block_id`), а не только к вкладке или отдельной диаграмме. | Принято |
| E2-021 | UI | Пользовательский дашборд не должен показывать слово `Codex`; в техлисте можно указать, что версия подготовлена с помощью Codex. | Принято |
| E2-022 | UI | Базовая визуальная схема — Executive Dark, полупрозрачные карточки поверх травы, но таблицы и тексты остаются читаемыми. | Принято |

## Требования к диагностике

Техлист Edition 2 должен показывать для ключевых KPI:

- `metric_id`;
- найденную строку источника;
- source sheet/report;
- `match_score`;
- `month_key`;
- тип агрегации: `period_sum`, `period_end`, `period_average`, `source_percent_row`, `calculated_fallback`;
- строки, включенные в группу;
- строки, исключенные из группы.
