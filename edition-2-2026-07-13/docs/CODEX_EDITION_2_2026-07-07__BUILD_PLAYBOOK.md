## Обязательный аудит proxy перед публикацией

Перед публикацией новой папки GitHub Pages выполнить живой `get_all`-контроль proxy и не доверять только фронтовому кэшу.

Проверить минимум:

- `pnl_data` существует и идет из правильной базовой вкладки ОПиУ. Для текущего Config это `(ENG) PnL Year`, найденная по gid строки `opiu`.
- `payment_data` и `payment_plan_data` не одинаковые: `payment_data` должен быть листом `Свод`, `payment_plan_data` — листом `Плановый реестр`.
- `dds_operations_data` не обрезан прежним лимитом 3000 строк; ожидается полный массив операций/кошельков.
- `raw_reports` содержит `source_url`, `sheet_name`, `spreadsheet_id` и количество строк для загруженных источников.
- Процентные KPI матчатся на процентные строки, а не на денежные строки:
  - `margin_pct` → `Contribution margin ratio, %`;
  - `gross_margin_pct` → `Gross margin, %`;
  - `op_margin_pct` → `Operating margin, %`;
  - `np_margin_pct` → строка рентабельности ЧП.
- После загрузки локальный фронт должен перейти из `КЭШ — Google Sheets` в `LIVE — Google Sheets`; кэш можно использовать только как промежуточный экран.

## Контрольные зоны

- P&L waterfall не должен показывать маржу больше выручки из-за ошибки знаков.
- Процентные маржи должны браться из строк источника, если строки есть.
- Если Google Sheets/proxy возвращает процентные строки как доли (`0.37`), фронт обязан нормализовать их до процентов (`37%`) перед выводом.
- D/E не должен включать accounts payable и прочую операционную кредиторку.
- Cash должен соответствовать концу выбранного периода.
- Total NCF имеет приоритет над суммой трех NCF-блоков.
- Default period нельзя расширять только из-за snapshot-строк cash или частичного ДДС текущего месяца. Если P&L за новый месяц еще не заполнен, период по умолчанию остается на последнем полезном P&L-месяце.
- При мерже live-ответа фронт должен очищать резервные demo-поля перед заполнением, иначе могут остаться старые `lt_debt/st_debt`, FTD или другие KPI.
- D/E требует явных слов про debt/equity, долг, заемный капитал, рычаг или леверидж; короткий токен `D/E` сам по себе опасен, потому что может случайно совпасть с посторонними строками.
- `assets_total` должен матчиться только на строки с `Активы` / `Assets`; не использовать `Валюта баланса` как самостоятельный alias, чтобы не цеплять расчетные/пояснительные строки.
- Для медленного Apps Script proxy использовать таймаут не меньше 180 секунд, иначе фронт может показывать вечное `обновляю Google Sheets...` при фактически рабочей загрузке.
- `var_costs` должен матчиться только на строки `Переменные` / `variable costs`. Запрещено использовать `Затраты на трафик` как alias или fallback для переменных расходов.
- Таблицы источников нельзя перегруппировывать эвристикой, если источник уже имеет собственную структуру. Для ДДС, баланса, платежного календаря и трафика показывать исходную таблицу одной свернутой секцией; для `Проекты Rocket` сохранять проектные секции из исходного листа.
- Все раскрываемые исходные таблицы по умолчанию должны быть свернуты.
- Если traffic-лист является матрицей `показатели строками / источники колонками`, FTD и Dep count нужно извлекать по строкам `-ftd месяц` и `-dep месяц`, а не ждать, что общий matcher найдет месяцы в колонках.
- В пользовательских KPI не показывать диагностические подписи вроде `source row`; диагностика должна жить на `Тех. листе`.
- Если служебный источник нужен для расчёта пользовательского блока, его нужно читать даже при `visible=false` в Dashboard Config. Пример: `dds_operations` скрыт как отдельная вкладка, но обязателен для карточки и таблицы остатков денежных средств по кошелькам на вкладке `Плат.календарь`.
- Для source-таблиц сначала сохранять структуру исходного листа, затем добавлять управленческую сводку сверху. Не прятать крупные строки источника внутрь первой найденной строки: для ДДС строки `Pos CF`, `Neg CF`, `NCF`, `Cash at End`, для баланса строки активов/капитала/обязательств должны оставаться верхним уровнем.
- Во всех табличных выводах подписи статей, названия проектов, источники и текстовые комментарии выравнивать влево; числовые значения выравнивать вправо и показывать tabular-цифрами.
- Первая колонка source-таблиц всегда должна быть закрепленной колонкой `Показатель`: если исходный лист содержит перед названием пустую колонку, буквенный код или служебный маркер, фронт переносит найденное название статьи в первую колонку, а не закрепляет служебный столбец.
- Денежные значения в презентационных таблицах и на осях графиков показывать в тысячах без знаков после запятой; проценты показывать без десятых, кроме малых значений меньше `0.5%`; коэффициенты показывать с одним знаком.
- Длинные названия строк в таблицах ограничивать двумя строками, полное название оставлять в `title` при наведении.
- На графиках показывать значения на столбцах/точках, но не на круговых и радарных диаграммах, чтобы не перегружать визуал. Денежные значения подписывать в тысячах, проценты определять по названию показателя, а не только по второй оси.
- Под каждым графиком добавлять короткую презентационную подпись: что показывает диаграмма и какой вывод виден по текущим данным. Эти подписи не заменяют заметки докладчика, а помогают быстро читать блок.
- Карточки коэффициентов должны показывать норму и формулу muted-текстом: например `current assets / current liabilities`, `(equity + long debt) / assets`, `долг = D/E × equity`.
- Долговая структура не должна включать операционную кредиторку. Если source не дает явные строки займов/кредитов, сумму долга для отображения брать как `D/E × equity`, а кредиторскую задолженность показывать отдельно только в балансовых обязательствах.
- Для traffic matrix `показатели строками / источники колонками` строить отдельную сводку по источникам: revenue, traffic cost, margin income, ROI, FTD, Dep, ARPU/CAC/LTV при наличии строк. ROI нормализовать: если источник отдал коэффициент `1.08`, в презентационном слое показывать `108%`.
- Для ЦКП source-лист читать по структуре: строка `Период`, далее блоки `ЦКП N — название`, внутри строки `Критерии`. Если перед январем есть декабрьский столбец, фронт сопоставляет месяцы по порядку с offset, а не по тексту даты. В карточке ЦКП показывать критерии, последний месяц и среднее за период; диаграмма справа строится по числовым критериям выбранного периода.
