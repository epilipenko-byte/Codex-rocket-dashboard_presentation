# CODEX_EDITION_2_2026-07-07 — требования к дашборду

## Цель

Создать отдельную живую версию финансового дашборда Edition 2, опубликованную на GitHub Pages с `edition-2` и датой в названии. Edition 1 не перезаписывать.

## Периоды и месяцы

1. Дашборд не должен иметь жестко зафиксированный период в коде, заголовке, селекторах или графиках.
2. Apps Script proxy обязан возвращать:
   - `month_keys`: `["2026-01", "2026-02", "2026-03"]`;
   - `months`: `["Янв", "Фев", "Мар"]`.
3. `month_keys` — источник истины периода.
4. Фронт сортирует, дедублирует и выбирает полезный диапазон по `month_keys`.
5. Значение по умолчанию: от первого месяца года с полезными данными до последнего месяца с полезными данными.
6. Flow-показатели считаются по диапазону, snapshot-показатели берутся на конец периода.

## Нормализация строк

1. Строки ищутся по названию, а не по позиции.
2. Поддерживаются русские и английские названия.
3. Нормализация: регистр, пробелы, пунктуация, `ё/е`, распространенные сокращения.
4. Fuzzy matching допустим, но диагностика обязана показывать confidence.
5. Общие слова не должны создавать ложные совпадения.

## P&L / ОПиУ

1. Водопад P&L строится из нормализованной структуры отчета.
2. Расходы отображаются красным вниз.
3. Маржи берутся из процентных строк источника, если они есть.
4. Таблица ОПиУ раскрываемая.
5. Нулевые будущие месяцы не выводятся.
6. Частично заполненные месяцы выводятся, но помечаются диагностикой.

## Проекты Rocket

1. Вкладка `ОПиУ блоки` переименовывается в `Проекты Rocket`.
2. Каждый проект отображается отдельным блоком.
3. Внутри проекта — раскрываемая P&L-структура.

## Ludens Group

1. Вкладка `Консолидация` переименовывается в `Ludens Group`.
2. Применяются те же правила раскрываемых строк и периодов.

## ДДС

1. Главный общий денежный поток — `Total NCF — Monthly Cash Change`, если строка найдена.
2. Если строки нет, fallback: NCF Operational + NCF Investment + NCF Financial.
3. Дивиденды ищутся отдельной строкой.
4. Корректировки, перемещения, займы и конвертации показываются отдельным раскрываемым блоком.
5. Cash at End of Month берется из итоговой строки, соответствующей выбранному `period_to`.

## Результаты

1. Вкладки `Задачи` и `Результаты` объединяются во вкладку `Результаты`.
2. Ссылки на внешние дашборды берутся из Dashboard Config.
3. Пороговые карточки называются `Целевые метрики`.

## Заметки докладчика

1. Заметки редактируются прямо из дашборда.
2. Основная привязка — к блоку графиков (`block_id`).
3. Один ряд/группа графиков имеет один раскрываемый блок заметок под собой.
4. Название листа не должно конфликтовать с существующим `Notes`; рекомендуемое имя: `Speaker Notes`.

## Техлист

1. Последняя вкладка показывает Dashboard Config блоками.
2. Таблицы визуально близки к Dashboard Config.
3. Ошибки/логи показываются в обратном порядке: новые сверху.
4. В техлисте можно указать, что Edition 2 подготовлена с помощью Codex.
## Дополнение 2026-07-14 — финальная визуальная и табличная правка

- Интерфейс должен использовать единый шрифт во всех темах, карточках, таблицах, кнопках и графиках.
- Активная вкладка выделяется спокойным цветом текущей темы, без яркого cyan/blue по умолчанию.
- Тема `Clear` должна сохранять читаемость, но быть заметно прозрачнее: фон должен частично просматриваться через карточки и диаграммы.
- Кнопка `Скачать` не должна использовать нативный download flow, который ломается в desktop-приложении; допустимый безопасный вариант — открыть печатную HTML-версию отчета и предложить сохранение через PDF/печать.
- Платёжный календарь должен выводить блок последнего месяца выбранного периода из листа `Свод`: недельные колонки `план / факт / Разница`, месячные итоги `план мес / факт / Разница мес`, строки в исходной группировке.
- В раскрываемых source-таблицах столбцы горизонтального/вертикального анализа должны быть явно подписаны как анализ, а не выглядеть как повтор месяцев.
